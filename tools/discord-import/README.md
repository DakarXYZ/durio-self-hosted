# Импорт истории из Discord

**English summary.** `discord_import.py` imports channel history exported with
[DiscordChatExporter](https://github.com/Tyrrrz/DiscordChatExporter) (JSON format) into text channels of a
dur.io server: messages keep the original author name and avatar, dates, edits, pins and replies; local media
files are uploaded as attachments. It uses the admin import endpoint (`0.16.0-fork.3` or newer) and needs an
instance administrator with TOTP 2FA. Python 3.10+, standard library only, Windows and Linux. Commands:
`check` → `dry-run` → `import --limit 50` (test) → `import`; `status` shows progress. Resumable.

Инструмент переносит историю каналов Discord, выгруженную
[DiscordChatExporter](https://github.com/Tyrrrz/DiscordChatExporter) в формате JSON, в текстовые каналы
сервера dur.io. Запускается на любом компьютере, где лежит экспорт (Windows или Linux, Python 3.10+, без
сторонних библиотек), и обращается к серверу по HTTPS.

## Что переносится и как это выглядит

- Сообщения появляются в выбранных каналах dur.io **с исходными датами** и в исходном порядке, вперемешку с
  новыми сообщениями их не будет — архив встаёт «в прошлое» канала.
- Автор — «фантом»: исходное имя (никнейм на сервере Discord, иначе имя пользователя, до 32 символов) и
  аватар, если он был скачан при экспорте, с пометкой **«Архив»**. Это не настоящие аккаунты: под ними
  нельзя войти, им нельзя написать, в архивных сообщениях нельзя открыть профиль автора. Боты помечаются
  как боты.
- Сохраняются: текст (markdown Discord и dur.io почти совпадает), отметка «изменено» с датой, закреплённые
  сообщения, **ответы** (в том числе на сообщения из других импортируемых каналов), файлы-вложения (до 10 на
  сообщение). На архивные сообщения можно отвечать как на обычные.
- Упоминания `@человек`, `@роль`, ссылки на каналы и свои эмодзи превращаются в текст (`@Ник`, `#канал`,
  `:emoji:`); ссылка на канал, который тоже импортируется, становится ссылкой на канал dur.io. Метки времени
  `<t:…>` — дата в UTC (`2023-11-14 22:13 UTC`; относительные «2 дня назад» тоже показываются датой).
- Стикер — строка `[стикер: имя]`. Пересланное сообщение — цитата
  `↪ Пересланное сообщение (дата):` + текст через `> ` (и его файлы). Итог опроса — строка
  `📊 Опрос «…» завершён. Победил ответ «…» (2 из 5 голосов).` (сами опросы DiscordChatExporter не выгружает).
- Файл, который не переедет (в экспорте только ссылка на CDN Discord, файла нет на диске, файл больше лимита
  сервера, сервер его не принял, больше 10 файлов в сообщении), — строка `[имя пал жертвой переезда]`.
  Сообщение, в котором **кроме таких файлов ничего нет** (ни текста, ни стикера, ни переехавшего файла),
  **не импортируется**; ответы на него становятся обычными сообщениями.
- **Превью ссылок** — те, что показывал сам Discord (заголовок, текст, сайт, картинка или видео), — переносятся
  отдельной командой `embeds` после импорта (шаг 6а): картинки превью, сохранённые с экспортом, загружаются на
  сервер, поэтому превью остаются и у мёртвых ссылок. Ссылка, у которой есть превью, в приложениях не
  повторяется в тексте — ссылкой становится заголовок.
- **Не переносятся:** реакции, ветки (threads),
  системные сообщения (вход на сервер, «закрепил сообщение», «создал ветку», бусты, ответы ботов на
  slash-команды и прочие числовые типы), пустые сообщения.
- Импорт **не присылает уведомлений** участникам.

## Что нужно

1. **Сервер с поддержкой импорта**: образ бэкенда `0.16.0-fork.3` или новее (см. «Обновление» в
   [README](../../README.md#обновление)).
2. **Администратор инстанса с TOTP**: аккаунт назначен через `--admins` и в нём включена двухфакторная
   аутентификация приложением-аутентификатором (шаги 3–4 раздела 10
   [инструкции по развёртыванию](../../docs/deploy-contabo.md#10-первый-аккаунт-администратор-приглашения)).
   Инструмент спросит код при входе и при включении режима администратора (на 60 минут; если импорт идёт
   дольше, код спросят снова — держите телефон рядом или запускайте частями через `--only`).
3. **Место на диске сервера** — не меньше суммы файлов, которую покажет `check` («файлов к загрузке»), с
   запасом. Проверка на сервере: `df -h`.
4. **Лимит вложений сервера** — по умолчанию 100 МБ; файлы больше `max_file_mb` (100) не загружаются. Если
   лимит на сервере другой, поставьте такое же значение `max_file_mb` в файле сопоставления.
5. **Python 3.10+** на компьютере с экспортом: `python --version` (Windows: установщик с python.org, галочка
   «Add to PATH»).
6. **Экспорт DiscordChatExporter** в формате JSON, по файлу на канал, **с медиа** (`--media --reuse-media`):
   рядом с файлами `.json` лежит папка `assets` (или та, что указана в `--media-dir`). Экспорт без медиа
   содержит только ссылки на CDN Discord, а они истекают через сутки.

## Порядок работы

### 1. Каналы в dur.io

В dur.io создайте на своём сервере текстовые каналы, куда пойдёт история (обычные каналы, не голосовые).
Можно импортировать и в существующий канал: архив встанет перед новыми сообщениями по датам.

Скопируйте **id** каждого канала. В Windows-клиенте или веб-версии сначала включите Настройки → «Расширенные» →
«Show 'copy ID' in context menus», затем правый клик по каналу в списке → **«Скопировать ID канала»**. Или
откройте канал в браузерном клиенте `https://<домен>/web/app/` — id канала (26 символов, например
`01ARZ3NDEKTSV4RRFFQ69G5FAV`) стоит в адресной строке после `/channel/`.

Для пробного импорта создайте ещё один канал, например `import-test`.

### 2. Файл сопоставления

Скопируйте [`mapping.example.json`](mapping.example.json) в `mapping.json` (рядом с инструментом или в любое
место) и впишите:

- `server` — адрес сервера, как его вводят в приложении, с `https://`;
- `export_dir` — папка с экспортом (на Windows можно писать `J:/Discord_bkp` с прямыми слешами);
- `channels` — пары «файл экспорта → id канала dur.io». Каналы, которых нет в списке, не импортируются;
  ответы на их сообщения отбрасываются (ответ превращается в обычное сообщение).

Необязательные настройки (`options`):

| Параметр | По умолчанию | Что делает |
| --- | --- | --- |
| `max_file_mb` | 100 | файлы больше не загружаются (строка `[имя пал жертвой переезда]`) |
| `batch_size` | 100 | сообщений в одном запросе импорта (максимум сервера — 100) |
| `max_batch_upload_mb` | 500 | пачка закрывается раньше, если её файлы набрали столько МБ |
| `link_channel_names` | `true` | `#general` в тексте → ссылка на сопоставленный канал dur.io |
| `import_avatars` | `true` | загружать аватары авторов |
| `progress_every` | 10 | строка прогресса каждые N пачек |
| `upload_reuse_minutes` | 30 | после обрыва повторно использовать уже загруженный, но ещё не привязанный файл, если он моложе |

### 3. Проверка без сети: `check`

```bash
python discord_import.py check --config mapping.json
```

По каждому каналу: сколько сообщений будет импортировано и сколько пропущено (системные по типам, пустые),
ответы (и сколько отброшено), вложения — локальные (и их объём), ссылки без файла, отсутствующие файлы,
слишком большие (с именами), число авторов; в конце — итог и сколько места займут файлы. Ошибки конфига
(файл не найден, id канала не похож на id dur.io, канал указан дважды) выводятся первыми.

### 4. Предпросмотр: `dry-run`

```bash
python discord_import.py dry-run --config mapping.json --samples 8
```

То же, что `check`, плюс несколько готовых сообщений по каждому каналу в том виде, в каком они уйдут на
сервер (обычное, ответ, с файлом, с пропавшим файлом, пересланное, со ссылкой на канал, стикер, опрос).
Сеть не используется.

### 5. Пробный импорт

Сделайте копию `mapping.json`, например `mapping-test.json`, где у одного канала стоит id тестового канала, и
импортируйте первые 50 сообщений:

```bash
python discord_import.py import --config mapping-test.json --only general --limit 50
```

Инструмент спросит email, пароль и код TOTP (пароль можно передать через переменную окружения
`DURIO_PASSWORD`, email — `--email`, первый код — `--totp-code`), покажет, что каналы найдены, и начнёт.
Посмотрите результат в приложении.

> [!IMPORTANT]
> Сервер вычисляет id архивного сообщения из исходного id и даты, поэтому одно и то же сообщение Discord
> нельзя импортировать дважды: при полном импорте эти 50 сообщений будут **пропущены** («пропущено
> сервером»), если они уже лежат в тестовом канале. Перед полным импортом **удалите тестовый канал** (вместе
> с каналом удаляются его сообщения) и файл состояния `mapping-test.state.json`.

### 6. Полный импорт

```bash
python discord_import.py import --config mapping.json
```

Каналы идут по очереди, в каждом — от старых сообщений к новым, пачками по 100. Файлы пачки загружаются
прямо перед её отправкой. Прогресс: сообщений сделано/всего, файлов и МБ загружено, скорость, оставшееся
время. `--only <канал>` (имя файла, имя канала Discord или id канала) — импортировать только его; можно
повторять. `--yes` — не спрашивать подтверждение.

**Время.** Сами сообщения идут быстро (сотни в секунду); основное время — загрузка файлов, она упирается в
исходящую скорость вашего интернета: 10 ГБ при 10 МБ/с — около 20 минут, при 1 МБ/с — около трёх часов.
Компьютер на это время не должен засыпать.

### 6а. Превью ссылок: `embeds`

После импорта канала (нужен сервер `0.16.0-fork.4` или новее):

```bash
python discord_import.py embeds --config mapping.json
```

Команда берёт превью Discord из экспорта и дописывает их к уже импортированным сообщениям (только до
последнего импортированного сообщения канала — сначала `import`). Картинки и видео превью, лежащие в
`assets`, загружаются на сервер (лимит ~1 файл в секунду, как у вложений); если в экспорте только ссылка
Discord на картинку (`general`), у превью остаются заголовок и текст, а картинка — только если это адрес
самого сайта, не Discord. Видео YouTube и подобных плееров не переносятся (их превью — картинка-обложка).
`check` показывает, сколько превью будет и сколько файлов к ним загрузить. Повторный запуск продолжает с
места остановки; `--only` и `--limit` работают как у `import`. Превью сообщения заменяются целиком, так что
запускать заново (с новым файлом состояния) безопасно.

### 7. Обрыв и продолжение

После каждого успешного запроса инструмент сохраняет состояние в `<config>.state.json` рядом с файлом
сопоставления (например `mapping.state.json`; другой путь — `--state`): последнее импортированное сообщение
каждого канала, загруженные аватары, счётчики и ошибки. Ctrl+C, обрыв сети или выключение компьютера
безопасны — запустите ту же команду снова, импорт продолжится с места остановки. Повторно отправленные
сообщения сервер просто пропускает.

```bash
python discord_import.py status --config mapping.json
```

показывает, сколько сделано по каждому каналу, и последние ошибки (например, файлы, которые сервер не
принял, — вместо них в сообщении строка `[имя пал жертвой переезда]`).

Не удаляйте файл состояния посреди импорта: без него инструмент начнёт сначала и заново загрузит все файлы
(сообщения сервер пропустит, но загруженные повторно файлы станут мусором, который сервер удалит позже).

### 8. Как отменить

Удалите канал в dur.io (настройки канала → «Удалить канал»): вместе с ним удаляются все его сообщения,
включая архивные. Чтобы импортировать заново — создайте новый канал, поменяйте id в `mapping.json` и удалите
файл состояния.

## Канал без медиа (`general`)

Если какой-то канал выгружен без `--media`, у его вложений в JSON вместо пути `assets\…` стоит ссылка
`https://cdn.discordapp.com/attachments/…?ex=…`. Такие ссылки подписаны и **истекают** — скачать по ним
уже нельзя, и `check` показывает их как «удалённых ссылок». При импорте каждое такое вложение станет строкой
`[имя пал жертвой переезда]`, а сообщения из одних таких вложений пропускаются («только с потерянными файлами»).

Чтобы сохранить файлы, **до импорта** этого канала выгрузите его заново с медиа в ту же папку — DiscordChatExporter
получит свежие ссылки и скачает файлы:

```bash
DiscordChatExporter.Cli export -t <токен> -c <id канала Discord> -f Json \
    --media --reuse-media --media-dir "J:/Discord_bkp/assets" -o "J:/Discord_bkp"
```

(в программе с окном — галочки «Download assets» и «Reuse assets» и та же папка для файлов; `--reuse-media`
не скачивает уже лежащие в `assets` файлы, тот же `-o` перезапишет JSON канала.) Для
`general` это около 55 ГБ и несколько часов. После этого снова выполните `check`: «удалённых ссылок» должно
стать 0, а на сервере понадобится соответственно больше места.

Если канал уже импортирован без файлов, переимпорт возможен только через удаление канала (см. «Как
отменить»): сервер пропускает сообщения, которые уже есть.

## Для разработчиков

- Контракт API: `POST /api/admin/import/channels/<id>/messages` и `/embeds` (режим администратора; второй —
  отладочный, без интерфейса в приложениях), загрузка файлов —
  `POST /autumn/attachments` и `/autumn/avatars`; формат запроса — в docstring `discord_import.py`.
- JSON экспорта читается потоково (файл на 300 МБ не помещается в `json.load` у 32-битного Python).
- Тесты чистых функций (разбор, конвертация, ответы, состояние): `python -m unittest` в этой папке.
